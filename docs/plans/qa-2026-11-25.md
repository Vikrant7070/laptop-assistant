# QA report and plan — 2026-11-25

## How it was tested

- On a **throwaway copy** of Nova (master `247e7e2`, port 5091, a copy of the user's knowledge / facts / skills /
  task history, no keys, phone, Gmail or connectors, so local brain `qwen3-vl:4b-instruct` only). The real Nova and
  its data were not touched. Cloud brains were **not** tested (that would spend the user's free quota).
- **UI:** every page (`/`, `/tasks`, `/knowledge`) and all 10 settings tabs, on desktop and at 375 px:
  all load, no console errors, no sideways scroll.
- **44 requests the way the user talks** (`qa_sweep.py`): greetings, memory, facts, Hinglish, maths, apps and
  follow-ups ("close it"), typos, YouTube, volume, CPU / disk, files in a sandbox, undo, impossible asks, a
  dangerous delete (answered No), email with no Gmail, a schedule, research, job status, window list, goodbye.
- Plus the task exam earlier the same day (25 tasks: 80 % success / 8 % false "done" / 12 % honest; PR #96).

## What works

Memory (save and recall a fact), maths, Hinglish ("kitna battery bacha hai?" → 31 %, charging), disk and CPU,
opening apps (checked by code), volume, the schedule card and "never mind", the research job (2 s to start),
job status, the window list, the dangerous delete (she asked first), the honest "not installed" for a made-up app.

## Research (2026-11-25)

- **Voice replies**: plain text, no emoji / markdown, one to three sentences; scope the rules to spoken turns
  ([LiveKit prompting](https://docs.livekit.io/agents/start/prompting),
  [NVIDIA voice agent prompts](https://docs.nvidia.com/nemo/labs-voice-agent/build-voice-agents/configure/system-prompts)).
  Nothing found on filtering, so Nova's filter is our own: it only removes what is never content (aside lines,
  a trailing run of 2+ emoji).
- **Small models and tool arguments**: flat, explicit, required parameters, with the schema in the prompt, and
  checking / repairing arguments in code ([13 local LLMs on tool calling](https://www.jdhodges.com/blog/local-llms-on-tool-calling-2026-pt1-local-lm/),
  [flat schemas](https://dev.to/docat0209/why-llms-suck-at-calling-apis-and-how-flat-schemas-fix-it-o0j)) → the
  separate `name` field for `create_folder`.
- **Failed attempts in the context**: a failed run left in the history biases the next task; keep a short
  summary of what failed instead of the transcript ([Thoughtworks: context rot](https://www.thoughtworks.com/insights/blog/generative-ai/what-is-context-rot),
  [arXiv 2606.14589](https://arxiv.org/pdf/2606.14589)) → P2-a.
- **YouTube search**: `https://www.youtube.com/results?search_query=<words>` (used by Invidious and search APIs;
  not officially documented, so it can change) ([Invidious](https://www.github.com/iv-org/invidious/pull/4146)).

## Fixed in this PR

1. `conversation.py`: the promise nudge doesn't fire when a step already ran in the task (`task["did"]`), and
   "all set" isn't a promise. (Line count unchanged: 798 / 800.)
2. `shared.tidy_reply` / `tidy_message`: aside lines and a trailing emoji pile are removed from the reply on
   screen **and from her history**, so she stops copying them. Speech already dropped them.
3. `prompts/system.md`: "This app is called Nova… never correct them"; "no asides in brackets or stars, at most
   one emoji". (A prompt change: the task exam was run before, on the same code, and is run after.)
4. `create_folder(path, name)`; the read-back and undo use the same target (`files.folder_target`).
5. `open_website("youtube <words>")` / `"<words> on youtube"` opens the results page; `fill_in` points YouTube and
   Google searches there; and "open youtube and search X" / "search X on youtube" is done by code first
   (`intents.YOUTUBE_SEARCH`, golden cases incl. near-misses, in `body.look_first`).
6. `undo_last_change("that")` doesn't reach past a request that changed nothing.

**Re-test on the copy after the fixes** (16 of the requests): the folder chain worked (make → write → read), the
time answer was kept, "hi nova" wasn't corrected, no `*(…)*` lines or emoji tails. Still chatty, and "15% of
2400" once opened Calculator (52 s) - model variance, watched in the exam.

Tests: `tests/test_qa_findings.py`.

## Next (each waits for the user's go)

**P2-a — a failed task doesn't follow you. Built (2026-11-25):** `resume.fold_failed`, called from `body.answer`
before a new task starts. Not folded: "continue", "try again" (new intent `TRY_AGAIN`), a correction, a card's
answer, or a task that worked. Live check on a copy: a failed rename's 24 messages became one line; the next
request mentioned the missing file once (the user's request is kept, so "that folder" still works), the one after
was clean. Tests: `tests/test_fold_failed.py`. Design as planned: When a new request starts and the previous task ended failed,
stopped or "not done", the previous task's turns in the history are replaced by one line: "Earlier: <goal> —
not done (<the failing check>)." The task card keeps the full record (`/tasks`). "continue" / "try again" still
work because resume reads the card, not the history. Test: the QA sequence (folder fails → "what's in X?" answers
about X, not todo.txt).

**P2-b — fast small talk. Built (2026-11-25):** measured first - the model answers "hi" in 1.4-4 s on its own;
Nova's turn took 5-13 s because every message carried a different tool list (24 / 18 / 23 tools), so the model's
prompt cache missed and it re-read ~5,000 tokens. `intents.SMALL_TALK` (the whole message is a greeting, thanks,
"how are you", a joke or a compliment; 16 golden cases) -> no tools, no window list, no promise nudge. Live on a
copy: hi nova 13.1 -> 3.8 s, how are you 5.7 -> 3.0, joke 6.7 -> 3.0, thanks 7.3 -> 4.9, hi 8.1 -> 2.5 (and the
"Oops! Sorry" nudge is gone). An exact skill phrase ("good morning" -> morning-check) still runs the skill. Whole
lines in (brackets) are tidied like *(asides)*. Design as planned: Greetings, thanks, jokes and "how are you" don't need tools: a short-reply route
(the brain called with no tools and a 1-sentence limit) when `toolpick` finds no tool above its floor and the
request has no laptop words. Expected: 12 s → 3–5 s for "hi". Measure with the exam's `questions` group plus a
"chat" group added to `exam/tasks.toml`.

**P2-c — Windows 11 Notepad. Built (2026-11-25):** two causes, both fixed. (1) Windows 11 Notepad asks "Save /
Don't save / Cancel" *inside its own window*; Nova only looked for a separate dialog, said "Closed", and the
read-back then failed - `window_action` now reads the window's buttons (`forms.buttons_in`) and, unless the user's
own words say "without saving" (`intents.DISCARD_CHANGES`; `judging` drops the brain's `discard_changes`
otherwise), tells the user and forbids terminal / taskkill. (2) With two Notepad windows open, the read-back asked
"is any Notepad open?" after closing one - it now checks the window it closed, by title. Live on the real Notepad:
"close notepad" found the prompt (buttons seen: Save, Don't save, Cancel), asked the user, 17.5 s (was 175 s with
3 terminal attempts). "Without saving" was tested on the fake desktop only (not on real unsaved tabs).
Design as planned: Close by the tab the task opened (its title is known from `open_app` /
`type_text`), and on the unsaved-changes prompt answer "Don't save" only when the user said "without saving";
otherwise ask. Never fall back to a terminal `taskkill` for an app window.

**P3 — built (2026-11-25).** #9: "switch to X" with an X window open is a focus step by code (`intents.SWITCH_TO`
in `body.look_first`); no such window -> the brain as before. #10: "what can you do?" -> `body.CAPABILITIES_REPLY`,
a list of what is really built, with no brain call. Live on a copy: the focus step ran and its check passed
(Calculator in front); the list came back in 0.0 s.

All ten QA issues are fixed (PRs #97-#101).
