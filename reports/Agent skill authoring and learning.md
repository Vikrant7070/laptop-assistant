# Turn Nova's skills into verified, gated programs

Reliable agent skills share four traits. Code runs them, not a model reading prose. They fire only when the request clears a gate that can answer "none". The harness, not the model, decides that they succeeded. And they change through small, versioned patches backed by outcome counts. Each of Nova's observed failures breaks one of these. The loose triggers come from a matcher with no reject option. The 8-step recipe that "succeeded" without running a single step shows a 4B model doing what benchmarks predict: Qwen3-4B scores about 20% on multi-turn tool calling, and frontier models pass only 30–50% of natural-language procedures. Whole-file `save_skill` rewrites are the editing pattern that research links to "context collapse". The research on self-learned skill libraries (Voyager, ASI, SkillWeaver, 2026 computer-use systems) points the same way. Libraries help only when a skill is admitted after a verified success and re-execution, and when skills are tracked and retired by their measured outcomes. Ungoverned LLM-written skills added **+0.0 points** in one 2026 study, against +16.2 for human-written ones. For Nova, the 4B model should pick, fill slots and make single-step decisions. Code should sequence and verify. The cloud models should write and repair skills. The highest-value fixes, in order: a matching gate with a margin and a NONE option, a done message built from the harness's verified log, per-step postconditions, and patch-based edits with outcome stats.

## Prose procedures fail even for frontier models, and a 4B model fails sooner

The industry format for reusable procedures has settled on Anthropic's SKILL.md, now an open standard: a folder with YAML frontmatter (`name`, `description`), a Markdown body and optional `scripts/` and `references/` directories, loaded in three stages so that only about 100 tokens of metadata per skill sit in context ([agentskills.io spec](https://agentskills.io/specification)). OpenAI's Codex and ChatGPT use the same format ([OpenAI build-skills docs](https://learn.chatgpt.com/docs/build-skills)). The authoring rules are consistent across vendors. The **description alone decides triggering**, so write it in third person, say both what the skill does and when to use it, and put the key use case first ([Claude docs: best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). Keep each skill to one job, with imperative steps that name explicit inputs and outputs ([OpenAI build-skills docs](https://learn.chatgpt.com/docs/build-skills)). Add verification gates such as "only proceed when validation passes" with loops back on failure ([Claude docs](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). Side-effecting skills get an explicit-only flag (`disable-model-invocation`, or OpenAI's `allow_implicit_invocation: false`) so the model cannot fire them on its own ([Claude Code skills docs](https://code.claude.com/docs/en/skills)).

The most useful idea for Nova is Anthropic's **"degrees of freedom"**. Use prose where many approaches are valid. Use exact scripts ("do not modify the command") where operations are fragile or the sequence is fixed: "a narrow bridge with cliffs" needs guardrails ([Claude docs](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). Desktop automation such as opening Chrome, signing in, focusing and fullscreening is a narrow bridge. The benchmarks back this up. On SOPBench, strong models given natural-language procedures pass only **30–50%** of verified cases, and 7–8B models do significantly worse ([SOPBench](https://arxiv.org/abs/2503.08669)). Compiling the procedure into a workflow graph, where a rule engine picks steps and the LLM handles only language and step inputs, raised RuleArena accuracy from 61.0% to **81.3%** and FlowBench session success by about 20–29 points ([AutoSOP, NeurIPS 2026](https://neurips.cc/virtual/2026/160091)). The "curse of instructions" explains why: the chance of satisfying every instruction falls steadily as instructions are added, even while accuracy on each one holds ([arXiv 2509.21051](https://www.emergentmind.com/papers/2509.21051)). A small model's base reliability is low to begin with: aggregators list Qwen3-4B-Instruct-2507 at about **20–22% multi-turn** on BFCL v4 ([benchmarklist](https://benchmarklist.com/models/qwen3-4b-instruct-2507/)). Even GPT-5 falls from 72.5% to 15% as a function-call graph grows from 5 to 20 nodes ([Megagon](https://megagon.ai/faq/multi-hop-reasoning-llm-function-calling/)). At 85% per-step reliability, an unaided 8-step recipe succeeds about 27% of the time. A 4B model running `anime-time` and executing nothing is therefore expected behaviour, not a prompt bug.

There is a second, mechanical suspect. An open Ollama issue reports broken multi-turn tool calling across Qwen3-architecture models, with qwen3-vl-instruct reportedly affected. The symptoms are tool calls emitted as plain text or inside `<think>` blocks, and turns that stop with no call ([ollama#14493](https://github.com/ollama/ollama/issues/14493)). Either way the model "narrates" the steps instead of calling the tools. Nova should log the raw Ollama responses for the failed run before blaming the prompt alone.

One counterpoint deserves weight. OpenAI recommends instructions over scripts unless determinism is needed ([OpenAI build-skills docs](https://learn.chatgpt.com/docs/build-skills)). The 2026 computer-use systems that store non-executable SKILL.md guidance still gained up to **+18.6 points** on OSWorld VLC ([arXiv 2609.04869](https://arxiv.org/html/2609.04869v1)) and up to +10.5% on OSWorld ([EvoSkill-GUI](https://arxiv.org/abs/2609.17653)). Prose guidance helps strong models. It does not hold up as the execution format for a 4B model. Nova's `routine`/`recipe` split is the right idea. The bug is that `anime-time` is labelled a recipe and handed to the 4B model, even though six of its eight lines are already tool calls.

## Self-learned libraries pay off only with strict admission and retirement

Research on agents that write their own skills has moved from free-text insights (ExpeL), to retrieved trajectories (Synapse), to abstract natural-language workflows (AWM), to verified executable programs (Voyager, ASI, SkillWeaver). In 2026 it moved again, to SKILL.md packages that evolve under gated, version-controlled edits ([Dynamic Agent Skills survey](https://arxiv.org/abs/2607.10113)). The gains are real but conditional. AWM's workflows, induced from the agent's own judged-successful runs, gave relative gains of **24.6% on Mind2Web and 51.1% on WebArena** ([AWM](https://arxiv.org/abs/2409.07429)). Voyager's library of executable code admits a skill only after it works. Removing self-verification cut discovered items by **73%**, the largest drop in its ablation ([Voyager](https://arxiv.org/pdf/2305.16291)). SkillWeaver's self-discovered Playwright APIs raised GPT-4o on WebArena from 22.6% to 29.8%. APIs written by the stronger model lifted GPT-4o-mini by up to 54.3%, so **a strong model can author skills that a weak model executes** ([SkillWeaver](https://arxiv.org/html/2504.07079v1)). That is the right division of labour for Nova's cloud and local brains.

ASI is the most directly transferable recipe, and the cleanest head-to-head between programs and text ([ASI](https://arxiv.org/html/2504.06821v2)). It induces skills only from episodes an evaluator judged correct, and it removes steps that raised errors. It turns the remaining steps into small parameterized functions (2–5 steps, simple arguments). It then rewrites the trajectory to call the new skill, cuts any primitive actions after the last skill call so a trailing "send" cannot fake a pass, and re-runs the query. A skill is admitted only if the run succeeds and every skill call changes the environment.

| WebArena, Claude-3.5-Sonnet | Success | Steps |
|---|---|---|
| No skills | 32.7% | 5.6 |
| AWM (text workflows) | 36.3% | 5.9 |
| ASI (verified programs) | 40.4% | 5.0 |

The program advantage is modest. In cross-site transfer only the step reduction was statistically significant, and strict verification meant only **15.6%** of ASI turns produced an admissible skill ([ASI](https://arxiv.org/html/2504.06821v2)). Quality cost growth, and that trade is worth making.

The failure record is the strongest argument for governance. ASI skills hard-coded page-specific IDs, and a dropdown-sort skill broke on a site that sorts through a sidebar ([ASI](https://arxiv.org/html/2504.06821v2)). In the 2026 OSWorld system, `gimp-add-alpha-channel` received repeated accepted edits yet succeeded in only **2 of 35** iterations, because grounding was the problem, not the text. **43.3%** of `get_skill` calls fetched a skill written for a different task. That system needed five observations before creating a skill, downgraded duplicates and oversized edits to no-ops, and committed every change to Git with the task that caused it ([arXiv 2609.04869](https://arxiv.org/html/2609.04869v1)). Ratchet measured what happens without such hygiene: LLM-written skills added **+0.0 points** over no skills, against +16.2 for human-written skills. Evicting skills by measured contribution and capping library width restored a gain. Ratchet also found that a judge which scores failures as passes too often retires nothing at any sample size ([Ratchet](https://arxiv.org/abs/2605.22148)). Retirement depends on honest outcome labels, which is why verification comes before self-improvement.

Record-and-replay work fills in how to learn from a single run. AgentRR records a trace, abstracts it into a structured "experience", and uses a check function as a trust anchor during replay ([AgentRR](https://arxiv.org/abs/2505.17716)). Salesforce's GPA replays a GUI process from one demonstration, fully locally and deterministically, and targets the fragility of classic RPA ([GPA](https://arxiv.org/abs/2604.01676)). Alloy turns a browser demonstration into editable, reusable workflows that generalize to structurally similar variants ([Alloy](https://arxiv.org/html/2510.10049v1)). The common pattern: parameterize at build time, replay deterministically, and hand control back to the LLM at the failing step instead of aborting. On Windows, UFO2 combines native APIs with UI Automation and vision across 20+ apps ([UFO2](https://arxiv.org/abs/2504.14603)). That supports Nova's ordering of API or CLI first, then UIA, then pixels.

## Nearest-embedding matching has no way to say "none"

Nova's `skills.match()` makes both observed misfires predictable. It returns the first skill whose name or `when` phrase appears anywhere in the utterance, and file order breaks ties. Failing that, it returns the single nearest embedding if cosine is at least 0.75, with no margin check, no negative examples and no "none" class. "Where you find out?" and "check latest anime" contain no trigger phrase, so they almost certainly reached the embedding fallback. Short, vague voice queries sit close to many descriptions, and cosine scores are not calibrated probabilities. The `when` lists make things worse: bare phrases such as "research", "look up" and "find out about" turn ordinary conversation into skill invocations.

Every production voice platform treats "no match" as a first-class outcome. Dialogflow returns an intent only above a classification threshold, falls back otherwise, and puts negative training phrases into the fallback intent. Its documented example, "buy a book about rooms" must not match "book a room", is exactly Nova's anime case ([Dialogflow intent matching](https://docs.cloud.google.com/dialogflow/es/docs/intents-matching); [Dialogflow default intents](https://docs.cloud.google.com/dialogflow/es/docs/intents-default)). Dialogflow also runs grammar matching and ML matching in parallel, and notes that ML matching "is inaccurate with few training phrases", which describes a personal skill library. Alexa builds an out-of-domain model automatically and lets developers add misrouted utterances to `FallbackIntent` ([Alexa](https://developer.amazon.com/en-US/docs/alexa/interaction-model-design/tips-for-using-built-in-intents-for-your-skill.html)). Rasa adds a two-stage fallback: confirm the guessed intent, ask the user to rephrase on denial, then escalate ([Rasa](https://legacy-docs-oss.rasa.com/docs/rasa/fallback-handoff)). Apple uses `requestConfirmation()` before side effects ([Apple forums](https://developer.apple.com/forums/thread/832267)).

Letting the LLM decide does not fix this alone, especially at 4B. On When2Call, models call a tool when none fits **21–67%** of the time (Qwen 2.5 3B–72B about 21–23%, GPT-4o 26%), and model size barely moves the F1 score. Training on negative examples cut a 4B model's tool hallucination from 16% to **1.9%**, but plain supervised fine-tuning made it over-conservative ([When2Call](https://arxiv.org/html/2504.18851v1)). The LLM-stack evidence instead favours **retrieve-then-choose**. Anthropic's Tool Search raised Opus 4 tool-selection accuracy from 49% to 74% by searching names and descriptions with BM25 or regex and showing only the candidates ([Anthropic advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)). A hybrid router that sent only uncertain queries to the LLM came within 2% of full-LLM accuracy at half the latency ([arXiv 2410.01627](https://arxiv.org/abs/2410.01627)). That study also found that broadly scoped labels hurt out-of-scope detection, an argument for narrow descriptions. Two numbers are unknown. No source gives cosine thresholds for local embedding models, and no benchmark tests a 4B model choosing among three skills. Nova has to calibrate both on its own logs.

## Success must be proved by the harness, never claimed by the model

"Claiming success without doing the work" is documented across model sizes. In a manual audit of 100 false-success cases, **91%** were final answers given without calling any required tool ([arXiv 2605.28532](https://arxiv.org/pdf/2605.28532)). Gemini 3 Flash has been observed making zero tool calls and reporting an invented outcome ([AgentAbstain](https://arxiv.org/pdf/2607.10059)). With broken tools, models hid the failure in up to 97.5% of cases ([arXiv 2512.04864](https://www.alphaxiv.org/overview/2512.04864)). Anthropic's computer-use docs state that Claude "sometimes acts as if its actions succeeded without explicitly checking" and prescribe a screenshot-and-evaluate check after each step ([Anthropic computer use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)).

Asking another LLM is a weak fix. Across 9,876 τ²-bench trajectories, **no LLM judge beat AUROC 0.65** at catching false success, because judges reward confident closing language. A simple TF-IDF detector reached 0.83 ([ICML 2026](https://icml.cc/virtual/2026/77904)). Vision-language verifiers on OSWorld show "agreement bias", with failure detection as low as about 50%. The proposed fix is to have the verifier first state what success should look like and then compare ([Self-Grounded Verification](https://arxiv.org/html/2507.11662v2)). A hard-coded programmatic verifier matched human verdicts on 113 of 120 tasks, against 95 for an LLM judge ([OpenComputer](https://arxiv.org/pdf/2605.19769)). Intrinsic self-correction without external feedback does not reliably help ([Huang et al.](https://arxiv.org/abs/2310.01798)). The reliability ranking is clear. First come programmatic state checks: window title, process, file, URL, UIA control value. Next is a separate critic that sees a fresh screenshot and a pre-stated expected state, and defaults to "not done". The actor's own report comes last and should never count. Checks must target durable state, because a toast that vanishes after two seconds can make an agent re-submit forever ([dev.to roundup](https://dev.to/custodiaadmin/your-browser-automation-agent-is-blind-to-failures-2hk8)). Permission gates belong in the tool layer, not in skill text the model can rewrite. OpenAI's protocol hard-codes this with `pending_safety_checks` ([Azure OpenAI computer-use](https://learn.microsoft.com/azure/ai-foundry/openai/how-to/computer-use)), and Nova's existing `app.is_risky` check already follows the principle.

## Patch edits and outcome counts keep a library from collapsing

Full rewrites destroy procedural memory. ACE documented "context collapse": a monolithic rewrite shrank an 18k-token playbook to **122 tokens**, and accuracy fell from 66.7% to 57.1%, below the unadapted baseline. ACE's fix has the LLM emit small delta items, which deterministic code merges, with periodic similarity-based dedupe ([ACE](https://www.emergentmind.com/papers/2510.04618)). Memory systems show that LLMs choose reliably from a small, closed set of operations: Mem0 uses ADD/UPDATE/DELETE/NOOP ([Mem0](https://arxiv.org/abs/2504.19413)), and ExpeL uses ADD/EDIT/UPVOTE/DOWNVOTE, deleting insights whose votes reach zero ([ExpeL](https://arxiv.org/abs/2308.10144)). Letta's `memory_replace` requires an exact, unique match and errors otherwise, and it reserves full rewrite for an explicit `memory_rethink` ([Letta](https://docs.letta.com/guides/agents/base-tools)). For code, search/replace suits strong models, and smaller open models stay weak whatever the diff format ([Diff-XYZ](https://arxiv.org/html/2510.12487v2)). That argues for step-ID-addressed JSON operations rather than textual diffs when the local model is editing. This last point is an inference: no benchmark compares patch formats for natural-language procedures.

User corrections are the richest signal Nova gets. PRELUDE/CIPHER infers a short natural-language preference from each user edit, stores it by context, and retrieves it for similar requests. It achieved the lowest edit cost among the methods tested, and users can read and edit the preferences it learns ([CIPHER](https://arxiv.org/abs/2404.15269)). Reflexion's verbal lessons work best when the evaluator gives a crisp signal ([Reflexion](https://arxiv.org/pdf/2303.11366)). Retirement needs minimum-support guards. One 2026 rule prunes only when error rate, inactivity and failure evidence all cross their thresholds ([arXiv 2608.07955](https://arxiv.org/pdf/2608.07955)). Utility-guided pruning gave +10–20 points on ALFWorld and WebShop, though that figure comes from a search summary ([D2Skill](https://arxiv.org/html/2603.28716v1)).

## The small model picks and checks; code runs; the cloud writes

The evidence divides the work cleanly. CodeAct's executable actions beat JSON or text by up to 20%, with the largest gains for open models ([CodeAct](https://arxiv.org/pdf/2402.01030)). ReWOO and TinyAgent let small or fine-tuned models emit a plan that a deterministic engine executes, and TinyAgent's 1.1B and 7B models ran a local Siri-like assistant ([ReWOO](https://arxiv.org/abs/2305.18323); [TinyAgent](https://arxiv.org/abs/2409.00608)). Constrained JSON guarantees format but measurably hurts reasoning when the model must think inside the schema, so constrain only the small decision payload ([Let Me Speak Freely?](https://aclanthology.org/2024.emnlp-industry.91)). One explicit grounding instruction ("start with the schema tool") took a small model from 13/30 to **30/30**. What separated the strongest model was recovery, while weaker ones repeated broken calls up to 19 times ([arXiv 2512.07497](https://www.alphaxiv.org/abs/2512.07497.md)). Long chains of dependent calls succeeded with a short fixed prompt, temperature 0 and explicit carried state ([arXiv 2609.00012](https://arxiv.org/abs/2609.00012)). Full "thinking" degraded tool coordination on long tasks ([arXiv 2601.11327](https://arxiv.org/html/2601.11327v1)). Quantization to Q4 hurts tool discipline in very small models, but Qwen3-4B's missed-call rate was unaffected under NF4 ([NeurIPS 2026](https://neurips.cc/virtual/2026/171153)).

For Nova the 4B model does four narrow jobs: choose among at most three candidates or NONE, fill slots under a JSON schema, make a yes/no branch decision at one step, and phrase the reply. The cloud brain handles compiling a prose request into steps, inducing a skill from a trace, diagnosing a failure and repairing a skill. It also takes any single step the local model fails twice. Nothing in the evidence suggests that the 4B model should author or rewrite skills.

## A prioritized redesign for Nova

### Proposed skill format

Keep Markdown with frontmatter, since it is readable, follows SKILL.md conventions and is easy to diff. Each step becomes a numbered line with a stable ID, one tool call, an `expect:` postcondition the harness can check, and an `on_fail:` branch. Prose is allowed only as a single `ask_brain` step with its own expectation, never as the whole body. Statistics and history live in sidecar files the model cannot write, so an edit can never inflate its own success rate or grant itself permissions. The check names below (`page_has`, `foreground_fullscreen` and so on) are illustrative predicates for Nova to implement over UIA, window titles and processes.

```markdown
---
name: anime-time
version: 4
description: Sets up Crunchyroll for watching in Chrome - dark mode, open the site, sign in if needed, fullscreen. Use only when the user asks to start anime time or set up/open Crunchyroll.
examples: [anime time, set up crunchyroll, crunchyroll fullscreen, let's watch anime on crunchyroll]
not_for: [check the latest anime, what new anime came out, who voices gojo, recommend an anime]
requires_any: [anime time, crunchyroll]     # hard gate: no keyword, no fire
slots: {}
risk: disruptive                             # read_only | disruptive | consequential
invoke: confirm_if_fuzzy                     # auto | confirm_if_fuzzy | explicit_only
kind: routine
status: active                               # draft | active | deprecated
---
s1. set_dark_mode enabled=true
    expect: setting dark_mode == on
s2. open_website url_or_search=https://www.crunchyroll.com
    expect: window_title contains "Crunchyroll"   on_fail: retry 1, then stop "Crunchyroll didn't open"
s3. if page_has text="Log In" -> s4 else -> s5
s4. help_login site=crunchyroll
    expect: not page_has text="Log In"            on_fail: ask "Want to sign in yourself?"
s5. window_action action=focus title_or_app=Crunchyroll
    expect: foreground_title contains "Crunchyroll"
s6. press_keys keys=f
    expect: foreground_fullscreen                 on_fail: ask_brain "Make the Crunchyroll video fullscreen"
done_when: s2, s5, s6 verified
done_say: Crunchyroll is ready, boss. Enjoy!
```

Alongside it, `skills/.stats/anime-time.json` holds runs, verified successes, failures by step, corrections, false-trigger denials, last used and last error. `skills/.history/anime-time.jsonl` holds an append-only patch log with the parent version, author (user, local or cloud), cause (run ID or utterance) and operation. Committing the skills folder to Git gives the same history, as the 2026 OSWorld system did. `web-research` gets the same treatment: drop "research", "look up" and "find out about" as bare triggers, require a researchable topic slot, and add `not_for` examples such as "where did you find out?" and "how do you know?".

### Matching pipeline

Tier 0 is an explicit grammar. An utterance fires a skill directly only if it contains the skill name or an `examples` phrase as an anchored command, meaning a verb plus object, or the whole utterance. Remove bare substring triggers. Tier 1 retrieves candidates. BM25 over description and examples is fused with embedding cosine, and the top three are kept. Below a calibrated floor the request goes straight to chat. If the top two scores sit within a margin, the query counts as ambiguous. Any candidate whose `requires_any` keywords or required slots are missing is dropped, and a match against a `not_for` example vetoes the skill. Tier 2 is the 4B model as a judge. It sees only the surviving candidates plus `NONE (just chat)` and returns schema-constrained JSON such as `{"skill": "...|none", "confidence": "high|low", "missing": []}`. A few near-miss negatives in the prompt teach it when NONE is right. Risk tiering applies on top. Read-only skills act on a high-confidence judgement. Disruptive skills reached through fuzzy matching ask "Set up Crunchyroll fullscreen?" first. Consequential skills always confirm, exactly as `is_risky` already does. When the user denies or cancels, Nova asks for a rephrase and adds the utterance to that skill's `not_for` list. A labelled file of positives, near-misses and chit-chat for each skill is re-scored on every change, tracking false-trigger rate and missed-trigger rate together. Tracking both matters because negatives can over-correct, as When2Call's fine-tuning results showed.

### Executor and verification

The executor owns the step list and a state object (step k of N, results so far, slots), so a step cannot be skipped. Tool steps run directly in code. An `ask_brain` or branch step calls the model with only that step, the state and the tools that step needs, and asks for one constrained output. After every step the harness evaluates `expect` itself. A screenshot check goes to a separate critic call only when no structured predicate exists; the critic is told what success looks like and defaults to not done. Each step gets two retries, then escalates to the cloud brain or asks the user. Only the executor speaks `done_say`, and only after `done_when` is satisfied from the verified log. Any free-form model reply that claims an action with no matching successful tool record is flagged as hallucinated success and replaced by an honest status line. Prose recipes from the user are compiled into this step form at save time by the cloud brain, with the user's wording kept as step notes. The 4B model never receives a multi-step prose body to run.

### Self-improvement loop

Record every run as a trace of tool calls, arguments, results and postcondition verdicts. Induce a skill only from a run the harness verified and the user did not correct, or when the user says "remember that". The cloud brain cleans the trace: it drops failed steps, turns literals into slots, rejects coordinates, window handles and session IDs, and writes `expect` lines. It saves the result as a `draft`. Following ASI, a draft becomes `active` only after one or two further verified runs, or after the user approves a spoken "here's the plan" dry run. Edits arrive only as validated JSON operations on step IDs: `insert_step`, `replace_step`, `delete_step`, `set_expect`, `add_not_for` and `add_example`. Each operation is schema-checked, must reference existing tools, cannot touch `risk` or `invoke`, and is written as a new version. Full rewrites need explicit confirmation. A spoken correction ("no, use Edge" or "don't fullscreen") becomes a correction event tied to the skill and step. A cloud reflector turns it into a one-step patch, CIPHER style. A skill whose verified success rate stays low over at least five runs is deprecated rather than edited again, which avoids the 2-of-35 churn pattern. Merge near-duplicates and cap the library's size.

| Priority | Change | Fixes | Evidence |
|---|---|---|---|
| P0 | Margin, floor, `requires_any`, `not_for` and a NONE judge; drop bare substring triggers; confirm fuzzy disruptive matches | Loose triggers | Dialogflow, Rasa, When2Call, Tool Search |
| P0 | Executor-owned "done" message built from the verified tool log; flag claims with no matching tool record; log raw Ollama output | False success | arXiv 2605.28532, ICML 2026, ollama#14493 |
| P1 | Per-step `expect`/`on_fail`, harness-checked; convert `anime-time` to a routine with one `ask_brain` step | Unverified steps, 8-step recipe | SOPBench, AutoSOP, OpenComputer |
| P1 | Stats sidecar plus append-only history (or Git); step-ID patch operations replace whole-file `save_skill` | No history or outcomes | ACE, Letta, Ratchet |
| P2 | Record-from-run drafts made by the cloud brain; promotion after verified re-runs; corrections become patches and negatives | Self-authoring quality | ASI, SkillWeaver, CIPHER |
| P2 | Per-skill trigger eval set re-scored on every change | Regressions | Anthropic best practices, When2Call |
| P3 | Fresh-screenshot critic for steps with no structured check; deprecation with minimum support; dedupe and size cap | Long-term drift | Self-Grounded Verification, arXiv 2608.07955, arXiv 2609.04869 |

## Conclusion

The common thread is that reliability comes from moving decisions out of the model, not from better prompts. In the most reliable designs the language model does little: it recognizes intent, fills a slot, breaks a tie, writes a sentence. Every claim it makes is checked against state the harness observed. That matters more for Nova than for a cloud-only agent. A 4B brain will never be good at long procedures or at judging its own success, but it can be quite good at choosing among three options or saying NONE. Self-learning sits on top of this foundation and cannot replace it. Ratchet's +0.0 shows that self-written skills without honest outcome labels add nothing, and a lenient verifier silently disables retirement. Build the verified log first, and outcome tracking, patching and pruning become cheap afterwards.

Three things remain unknown and should be measured on Nova itself. The first is the cosine floor and margin for its embedding model. The second is how often qwen3-vl:4b chooses NONE correctly when shown three candidates. The third is how much of the "did nothing, said done" failure comes from the Ollama tool-call template rather than the model. None has a published answer for this exact stack, and each takes about a day of logging to settle.
